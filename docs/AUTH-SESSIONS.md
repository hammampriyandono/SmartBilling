# Sesi login dan logout otomatis

Keputusan pengguna 5 November 2026: **semua akun (owner, tenant, viewer) otomatis keluar setelah 15 menit tanpa aktivitas pengguna**. Batas maksimum sesi delapan jam sejak login dan expiry/pencabutan akses visitor tetap berlaku. Mana yang tercapai lebih dulu memutus akses.

- Aktivitas: klik/pointer, gerakan mouse, ketikan/input, wheel serta sentuhan. Hanya event browser `isTrusted` yang dicatat. Polling grafik, `/auth/me`, pengambilan CSRF, focus dan visibility tidak memperpanjang sesi.
- Frontend mengirim aktivitas maksimal sekali per30detik dengan kiriman penutup untuk input berikutnya. `age_ms` (maksimal60detik) mempertahankan waktu input sebenarnya saat pengiriman ditunda, sehingga delay heartbeat tidak menambah waktu aktif. Kegagalan jaringan tidak memicu retry heartbeat terus-menerus tanpa input baru.
- `POST /api/auth/activity` memerlukan CSRF/origin dan login valid; account header dicek jika dikirim. Server memakai waktu server, memperbarui hanya `lastActivityAt` pada JSON `auth_sessions` secara atomik/monotonik, serta memeriksa idle dan expiry sebelum UPDATE. Sesi terhapus atau sudah kedaluwarsa tidak bisa dihidupkan kembali. Tidak mengubah `expiresAt` delapan jam, cookie, user role, atau grant viewer. Endpoint ini di namespace autentikasi; akses bisnis viewer tetap hanya baca.
- `requireUser` menolak setiap API terproteksi setelah deadline dengan HTTP401 `session_idle_expired`, termasuk bila JavaScript dimatikan atau tab belum memuat bundle baru. Sesi lama yang belum memiliki `lastActivityAt` memakai `issuedAt`, sehingga deploy tidak memberikan15menit baru secara diam-diam. Row sesi kedaluwarsa dapat tetap berada di tabel sampai pembersihan sesi existing; row itu sudah tidak dapat mengakses API. Login ulang meregenerasi sesi.
- `/auth/me` mengembalikan deadline idle, expiry absolut dan waktu server. Frontend memakai selisih waktu server untuk timer, memeriksa kembali saat deadline/tab bangun, dan memakai pemeriksaan server agar aktivitas tab lain pada sesi browser yang sama tidak menyebabkan logout keliru. Saat offline pada batas waktu, tampilan keluar; akses server tetap ditolak saat idle habis.
- Pesan login menjelaskan pengguna otomatis keluar karena tidak aktif. Sesudah pembaruan, refresh Ctrl+F5 dan login ulang agar browser memakai pelacakan aktivitas terbaru. Tab dengan bundle lama tetap menerima penolakan server tetapi belum mengirim aktivitas manusia.
- Membuka halaman masuk dalam kondisi belum login tidak menampilkan peringatan logout. Respons401 pemeriksaan awal merupakan kondisi normal; pesan error tetap ditampilkan untuk submit login yang gagal atau sesi yang sebelumnya aktif lalu berakhir.

Logout ini hanya untuk akses dashboard. MQTT, penyimpanan sensor, perhitungan backend, relay dan sesi RFID tap-ke-tap tetap berjalan sesuai alurnya; tidak otomatis menutup sesi fasilitas atau mengirim perintah perangkat.

Tidak ada migration, dependency atau konfigurasi rahasia baru. Pengujian memakai clock/timer simulasi dan PostgreSQL sementara; tidak menunggu15menit nyata atau mengubah timestamp sesi pengguna produksi. Hasil dan deployment aktual dicatat di HANDOFF.md.
